# Standardize PR Body Reviewability Defaults

## Intent

Improve the default PR body generated by the workflow so a human reviewer can identify scope, proof, and risk quickly without digging through comments or checks first.

## Sequencing

- Execution order: first
- Dependency role: establishes the reviewer-facing structure that `015`, `016`, and `017` should build on

## Specification

- Move the roadmap reference to the top of the PR body.
- Keep the summary section concise and human-readable.
- Add a standard `Evidence` section for screenshots or other proof artifacts when present.
- Add a standard `Test Coverage` section that explains new e2e or unit tests and what they verify.
- Keep validation visible, but lighter and less visually dominant than the summary.

## Acceptance Criteria

- [ ] Workflow-authored PR bodies always surface the roadmap path near the top.
- [ ] UI-oriented work includes an obvious evidence section when screenshots exist.
- [ ] Test additions are summarized in plain language instead of only implied by file diffs.
- [ ] Validation remains visible without overwhelming the rest of the PR body.

## Sunset

Dropped 2026-06-17 with the autonomous GitHub Actions pilot. Full rationale in `roadmap/index.md`: the remote AI execution payoff didn't justify the cost/effort for these projects.
